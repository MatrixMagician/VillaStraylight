description: "Self-improvement: build the capability that makes the next goal cheaper"
priority: 40
---
At a natural pause, assess whether a concrete weakness earns an improvement. Keep what works; do not
change the workspace for novelty. Decide the benefit, approach, and boundary before implementing.
Focused research may return facts or bounded alternatives when an unknown could change that decision;
do not investigate unrequested optimizations by default. First check whether this repo, the standard
library, an installed plugin, skill, live rule, or graphmind already covers it. Improve the installed
capability before proposing a parallel one. Offer `/quartermaster:resupply` only with current or
standing user approval; every recommended change still needs its own approval unless that exact class
is covered by standing permission.

- **A claim you could not check** (is it correct? does it fit the memory envelope? is offload real?)
  may need a measurement. Check whether `bench`, `doctor`, `verify`, or an existing proof can answer it
  first. Build a new instrument only when it is the smallest durable missing capability.
- **A multi-step task you did by hand** may belong in a skill (build it with skill-creator).
- **Something you re-derived or re-explored** belongs in `docs/`, `CONTEXT.md`, or a CLAUDE.md line.
- **A convention you had to be told** belongs in a tightly-scoped live rule.

Keep it to one evidenced improvement. If the existing capabilities hold up, say so explicitly.
