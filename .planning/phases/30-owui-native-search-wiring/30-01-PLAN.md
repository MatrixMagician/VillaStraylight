<objective>
Add the operator-tunable web-search result-count knob to `VillaConfig` as a new
`WebSearchResultCount int` field (D-05), default **3**, following the established
v1.5 web-search field discipline EXACTLY (the `SearxngPort` 4-site pattern):
struct field with `omitzero` tag, defaulted in `defaultConfig()`, self-healed in
`normalizeVilla()`, and zeroed in `marshalVilla()` when `!WebSearchEnabled`.

This is the config half of Phase 30 (SRCH-03's tunable result count). It is
independent of the orchestrate env-wiring (Plan 02) and lands first so Plan 02 can
thread `in.Cfg.WebSearchResultCount` into the OWUI render.

Purpose: Config is the single source of truth — the operator tunes the OWUI
`WEB_SEARCH_RESULT_COUNT` via `config.toml` (authoritative because Plan 02 emits
`ENABLE_PERSISTENT_CONFIG=False`). Default 3 keeps the context budget conservative
ahead of Phase 31's ctx-budget reservation.

Output: One new config field across its four lifecycle sites + extended config
tests proving default/self-heal/omit-when-off/round-trip.
</objective>
