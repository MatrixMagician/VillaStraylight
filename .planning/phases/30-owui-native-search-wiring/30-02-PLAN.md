`buildOpenWebUIView` with a `WebSearchEnabled`-gated ordered env block (D-01/D-02/

web-search-on case — the SC#4 env-name-churn drift guard.

DB-backed `ConfigVar`s, so `ENABLE_PERSISTENT_CONFIG=False` is mandatory and
load-bearing (identical rationale to the Phase-20 memory block, T-20-01).

result count. The per-query toggle and honest no-results are OWUI-runtime native
behaviors asserted by UAT (D-06) — Phase 30 builds NO villa guard/prompt/fetch path
(those are Phase 31/32).

Output: extended `openwebui.go` + `render.go`, one new golden, and the orchestrate
test extensions (drift + config-driven + single-emit) proving the contract.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| villa render → 0644 Quadlet unit | The OWUI env block is written into a world-readable systemd unit. No secret may appear here. |
| OWUI container → villa-searxng | OWUI calls SearXNG over `villa.network` by container DNS (no host bind, PRIV-01). The only sanctioned outbound is SearXNG's vetted engine allowlist (Phase-29 SRCH-04). |
| operator browser → OWUI (loopback :3000) | The per-session web-search toggle is OWUI-native, client-side; villa supplies env only and never overrides it. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-02-ID | Information Disclosure | secret leaking into the 0644 OWUI unit | mitigate | No secret is rendered into the OWUI env block; `SEARXNG_QUERY_URL` carries no credential (private instance, no SearXNG API key needed). The only web-search secret (SearXNG secret_key) stays in the 0600 `searxng.env` (Phase-29 T-29-02), never touched here. |
| T-30-02-OFF | Information Disclosure / Spoofing | routable bind / outbound when "off" | mitigate | The web-search env appends ONLY when `WebSearchEnabled`; off-render is byte-identical to v1.4 (D-07, proven by golden + `TestRenderByteIdenticalWhenWebSearchOff`) → zero-outbound posture unchanged (PRIV-07). OWUI→SearXNG is container-DNS over `villa.network`, no host port. |
| T-30-02-TMP | Tampering | env-name regression silently disabling telemetry-kill / privacy posture | mitigate | The bidirectional `TestRenderOpenWebUITelemetryFrozen` (count + full-set + telemetry-kill check) re-confirms the telemetry-kill set survives in the new web-search-on view; env-name churn fails by construction (SC#4). |
| T-30-02-URL | Injection (V5 Input Validation) | `SEARXNG_QUERY_URL` composition | mitigate | URL composed via `fmt.Sprintf` from config values only; no shell interpolation (fixed-arg render). The `<query>` token is OWUI's literal placeholder, never interpolated by villa with user input. |
| T-30-02-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install in this plan (Go stdlib `fmt`/`strconv`/`text/template`/`testing`; existing pinned OWUI + SearXNG images). No new dependency. |

  mitigated in Phase 30 — the native fetch path is left as-is. The
  sanitize/normalize/fence/classify guard layer is Phase 32 (GUARD-02/03/04). Do NOT

- **SSRF / page-fetch validation (GUARD-01/SSRF):** lives on the FETCH path, which
  this phase does NOT touch — OWUI's native fetch is replaced by `villa-websafe` in
  Phase 31. Not pulled forward.
- **Browser-side markdown-image zero-click exfil:** documented v1.5 residual
  (GUARD-04), not closed here.

block only on HIGH. The realistic surface for THIS env-wiring change is narrow and
mostly inherited from Phase 29; no HIGH finding is introduced.
