<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| disk → status/doctor/dashboard readers | The verify-state file is read later as the authoritative outbound-bounded signal; a torn/forged/stale file must not become a false "bounded" |
| caller → store | Save stamps the schema_version itself; it never trusts a caller-supplied schema |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-34-01 | Tampering | verify-search-state.json (torn/forged file → fabricated "bounded") | mitigate | Fail-closed Load (corrupt/future-schema/absent ⇒ empty State ⇒ downstream Unknown, never a fabricated PASS); atomic 0600 temp+rename write so no partial file is ever observed |
| T-34-02 | Information Disclosure | the state file on disk | mitigate | 0600 file / 0700 dir modes enforced by WriteFileAtomic (recall precedent); file holds only verdict+timestamp, no query/URL content (no ephemeral web data persisted) |
| T-34-03 | Spoofing (of a security property) | the persisted verdict feeding the bounded indicator | mitigate | Verdict is written verbatim from the real proof's verdictName; the freshness check that turns PASS→"bounded" lives in the status core (Plan 03), so a stale PASS cannot read as current |
| T-34-04 | Elevation / path traversal | WriteFileAtomic target path | mitigate | assertInsideDir guards the write against the FIXED storeRootDir() (local clone of the recall guard); fixed-arg path, no shell interpolation |
</threat_model>
