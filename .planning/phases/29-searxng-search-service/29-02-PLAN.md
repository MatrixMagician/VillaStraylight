<objective>
Implement the one genuinely net-new sub-pattern of Phase 29: rendering and mounting a `settings.yml` CONFIG FILE from config, PLUS writing the 0600 secret env file that keeps the secret out of the 0644 unit. Plan 01 produced the pure renders (`RenderSearxngSettings`, `RenderSearxngSecretEnv`); this plan adds the impure WRITERS — siblings of `WriteUnits` — that write (a) the rendered settings.yml and (b) the `searxng.env` secret env file atomically into a villa-owned config dir (`$XDG_CONFIG_HOME/villa/searxng/`), guarded against path traversal, at mode 0600. settings.yml is mounted read-only at `/etc/searxng:ro,Z`; the env file is the `EnvironmentFile=` target Plan 01's `.container` unit references (BLOCKER 1 — the secret reaches the container via this 0600 file, never via an inline `Environment=` literal in the 0644 unit).

`orchestrate` is the ONLY intentionally-impure first-party module, so these writers belong here as siblings of `WriteUnits` (render.go/reconcile.go stay pure). Neither file must land in the systemd unit dir (systemd would try to parse a non-unit file — Pitfall 1).

**Deliberate file-placement divergence from 29-PATTERNS.md (WARNING 4 — noted, not an accident):** PATTERNS framed the writer as a `reconcile.go` MODIFY (adding a `WriteSettings` sibling alongside `WriteUnits`). This plan instead puts the writers in a NEW `internal/orchestrate/searxng_settings_write.go` rather than appending to `reconcile.go`. Rationale: keeping the searxng-specific impure writers in their own file leaves `reconcile.go` (the content-hash idempotency core + the generic unit writer) focused and pure-ish, and co-locates all searxng write logic. The cloned/shared helpers (`assertInsideDir`, the atomic-write discipline) are reused from `reconcile.go` in the same package — the divergence is the file location only, not the discipline.

Purpose: SC#2 (a real `format=json` query) cannot pass without the container actually reading a mounted settings.yml that enables the json format + the bounded engines, AND reading its secret from the 0600 env file.
Output: traversal-guarded, atomic, secret-safe settings.yml + secret-env writers that the install flow (Plan 03) and lifecycle commands call.
</objective>
