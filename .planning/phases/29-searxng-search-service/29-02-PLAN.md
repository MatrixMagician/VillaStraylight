<objective>
Implement the one genuinely net-new sub-pattern of Phase 29: rendering and mounting a `settings.yml` CONFIG FILE from config. Plan 01 produced the pure render (`RenderSearxngSettings`); this plan adds the impure WRITER — a sibling of `WriteUnits` — that writes the rendered settings.yml atomically into a villa-owned config dir (`$XDG_CONFIG_HOME/villa/searxng/`), guarded against path traversal, at a secret-safe mode, so it can be mounted read-only at `/etc/searxng:ro,Z`.

`orchestrate` is the ONLY intentionally-impure first-party module, so this writer belongs here as a sibling of `WriteUnits` (render.go/reconcile.go stay pure). The settings.yml must NOT land in the systemd unit dir (systemd would try to parse a non-unit file — Pitfall 1).

Purpose: SC#2 (a real `format=json` query) cannot pass without the container actually reading a mounted settings.yml that enables the json format + the bounded engines.
Output: a traversal-guarded, atomic, secret-safe settings.yml writer that the install flow (Plan 03) and lifecycle commands call.
</objective>
