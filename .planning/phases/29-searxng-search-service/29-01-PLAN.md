<plan_decisions>
- **SC#1 `.volume` — DECIDED N/A (no `.volume` unit rendered).** ROADMAP SC#1 names `villa-searxng.container`/`.volume`. This plan intentionally renders ONLY `villa-searxng.container` and does NOT render a `.volume` unit. Rationale: a private, JSON-only SearXNG instance with `limiter:false` (no valkey DB) and `image_proxy:false` is effectively stateless — it needs no writable persistent volume (unlike Qdrant, which stores vectors). The settings.yml is supplied read-only via the `/etc/searxng:ro,Z` bind. SC#1's `/.volume` clause is therefore deliberately satisfied as **intentionally N/A**, not deferred to executor judgment. (If on-hardware UAT later surfaces a required writable state dir, adding a `.volume` is a one-line clone of `qdrant.volume.tmpl` + golden — but the plan does NOT leave this open: the default is no volume.)
</plan_decisions>

<plan_assumptions>
These RESEARCH Assumptions are carried INTO the plan but are surfaced for operator confirmation, not silently baked in. The executor implements them as written; if the operator overrides, the override is a config-driven change (the values are config-derived, not hardcoded in logic).

- **A1 (SRCH-04, security-sensitive) — the vetted engine subset.** Proposed `keep_only`: `duckduckgo`, `brave`, `wikipedia`, `wikidata`. Rationale: ≤4 upstream hosts, all high-trust general/reference engines; excludes Google/Bing direct (rate-limit/CAPTCHA self-hosted), social/forum engines (injection surface), and image/video engines (out of scope for v1.5 text grounding). This is the auditable outbound surface Phase 33's `villa verify search` will cross-check — keep it minimal. The list is rendered from a single source so a future operator change is a one-line edit + golden re-freeze.
- **A4 — the secret_key route (REVISED per checker BLOCKER 1).** Generate the secret ONCE via `crypto/rand` at first opt-in, persist in `config.toml` (0600 via existing `SaveVilla`), render READS it from config (so the golden uses a fixed test secret). The secret reaches the container via a Quadlet **`EnvironmentFile=<0600 path>`** directive — a separate `SEARXNG_SECRET=…` env file written at mode 0600 by Plan 02's writer (alongside settings.yml, same `atomicWrite`/`assertInsideDir` discipline). The `.container` unit is itself written at 0644 (world-readable, by `WriteUnits`), so an inline `Environment=SEARXNG_SECRET=<value>` literal WOULD leak the secret into a world-readable file (RESEARCH Pitfall 2) — therefore the template renders `EnvironmentFile=` (a path reference only) and contains NO secret value. NEVER rendered into the 0644 settings.yml or the 0644 unit; never `math/rand`; never logged.
</plan_assumptions>

|----------|-------------|
| config.toml (operator-editable, 0600) → render | Hand-edited config is untrusted input; render must fail closed, never widen a bind |

| villa-searxng container → upstream search engines | The ONLY sanctioned outbound from this service; bounded by the engine allowlist |
