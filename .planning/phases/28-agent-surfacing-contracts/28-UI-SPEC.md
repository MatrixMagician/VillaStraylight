# Phase 28 — UI Design Contract

> Visual and interaction contract for the new dashboard **Agent panel** (SURF-01, D-05).
> Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Scope & Binding Constraint

The ONLY frontend deliverable in Phase 28 is a new **Agent panel** added to the
embedded, no-build control dashboard (`internal/dashboard/assets/dashboard.{html,css,js}`,
served verbatim via `go:embed`; `dashboard.html` is parsed as an `html/template` shell).

**There is NO JS toolchain / bundler / component library.** The deliverable is hand-written
HTML + plain CSS custom properties + vanilla JS only. No React / Tailwind / shadcn / npm.
The shadcn initialization gate is **not applicable** to this stack.

**CONTEXT.md D-05 is the locked contract:** the Agent panel MIRRORS the existing **Memory
panel** treatment exactly — same panel chrome, spacing, typography, and color tokens —
rendered **hidden-until-data**: the panel ships with the `hidden` attribute and is unhidden
ONLY when the status JSON contains a `coding` block (agent enabled). When `report.coding` is
absent, the panel re-hides, so a coding-off dashboard renders pixel-identical to v1.3.

This contract therefore **does NOT introduce a new visual language.** The design system
below is the existing dashboard system, extracted verbatim from `internal/dashboard/assets/dashboard.css`.
All declared values are the project's real, shipped tokens — none are fabricated. The
executor reuses the existing `.panel` / `.panel-heading` / `.metric-row` / `.badge` classes
and the existing JS DOM helpers (`metricRow`, `mutedP`, `memoryBadgeRow`, `groupThousands`).

## Typography

Declared roles (existing tokens — 4 sizes, 2 weights, reuse verbatim):

| Role | Size | Weight | Line Height | Usage in Agent panel |
|------|------|--------|-------------|----------------------|
| Display | 28px | 600 | 1.2 | Header `<h1>` only (not in this panel) |
| Heading | 20px | 600 | 1.2 | `.panel-heading` — the "Agent" panel title |
| Body | 16px | 400 | 1.5 | Default text, `.muted` empty/Unknown copy |
| Label | 14px | 400 | 1.5 | `.badge` text, mono value rows (`.metric-value`, 14px mono tabular-nums) |

**Font weights used:** regular (400) for body/values; semibold (600) for the heading and
metric labels (`.metric-label` inherits; emphasis on `.health-service`/`.model-id` idiom is
600). No third weight.

**Value rendering rule (binding, from existing Memory/usage precedent):** all numeric and
identity values (version, model id, mode, residency, token counts, cache ratio) render in
`--font-mono` with `font-variant-numeric: tabular-nums` via the existing `.metric-value`
class, so 2–3s poll updates never reflow the layout. Token totals use `groupThousands()`
(e.g. `1,284,907`). Version/model strings render verbatim — never reformatted.

## Color

Declared roles (existing `:root` 60/30/10 split — reuse verbatim, introduce NOTHING new):

| Role | CSS var | Value | Usage |
|------|---------|-------|-------|
| Dominant (60%) | `--bg-dominant` | #0F1115 | Page background (panel inherits page) |

| Accent (10%) | `--accent` | #3B82F6 | NOT used inside this panel — see reserved list |
| Destructive | `--destructive` | #EF4444 | NOT used inside this panel (no destructive action here) |

Supporting neutrals + semantic status (outside the 60/30/10 budget — these carry the panel's meaning):

| Role | CSS var | Value | Usage in Agent panel |
|------|---------|-------|----------------------|
| Text primary | `--text-primary` | #E6E8EC | Labels, identity values |
| Text muted | `--text-muted` | #9AA0AA | `.muted` empty/Unknown copy, mono values |
| Border | `--border` | #2A2E37 | Panel border, row dividers, neutral badge frame |
| Status ready (PASS) | `--status-ready` | #22C55E | `badge-ready` — agent enabled, pin **matches** |
| Status warn | `--status-warn` | #F59E0B | `badge-warn` — pin **mismatch / drift** (amber, NEVER red) |
| Status unknown | `--status-unknown` | #6B7280 | `badge-unknown` — typed-Unknown (cache effectiveness / pin unevaluable) |

**Accent reserved for (unchanged, panel-external):** chat link, the Switch button
(`.btn-primary`), the loaded-model left-border (`.model-loaded`), and keyboard focus rings.
**The Agent panel MUST NOT use the accent** for any of its own content — it is a read-only
status surface, exactly like the Memory panel.

**Destructive (red) reserved for (unchanged):** the restart-warning copy and the
connection-lost banner ONLY. Phase 28 has **no destructive action**, so red appears nowhere
in the Agent panel. A pin **mismatch** / version drift is a WARN (amber `badge-warn`), never
red — mirroring the Memory panel's `embedding_skew` mismatch treatment (D-10 precedent).

**Honesty color rule (binding):** an unevaluable signal (cache effectiveness when timings are
absent; pin match when the policy/binary comparison cannot be made) uses the GRAY
`badge-unknown`, never green and never red — the project's typed-Unknown convention.

## Component & State Inventory (Agent panel)

The panel reuses existing classes/helpers; this is the field + state map the executor implements.

**Static shell (`dashboard.html`)** — add after the Memory panel, mirroring it:
```
<section class="panel" id="agent-panel" aria-labelledby="agent-heading" hidden>
  <h2 class="panel-heading" id="agent-heading">Agent</h2>
  <div id="agent-body"></div>
</section>
```

**Render function (`dashboard.js`)** — a `renderAgent(report)` mirroring `renderMemory(report)`:
fed by the SAME `/api/status` poll (no new fetch/endpoint/probe); `report.coding` absent →
`agentPanel.hidden = true` and return; present → unhide, clear, repopulate via `metricRow` /
`memoryBadgeRow` / `mutedP`. Wire the call beside `renderMemory(report)` in the poll loop.

| Row / signal | Source field (D-03/D-09/D-10) | Rendered as | Honest absent/Unknown state |
|--------------|-------------------------------|-------------|------------------------------|
| Agent enabled | `coding` block presence | (panel visibility itself; no row) | Panel hidden entirely (D-02/D-05) |
| Version | `coding.version` | `metricRow("version", …)` mono verbatim | OMIT row if absent (never a placeholder) |
| Pin match | `coding.pin_match` (bool) | `memoryBadgeRow("policy pin", "match", "ready")` / `"mismatch", "warn"` | unevaluable → `("policy pin","unavailable","unknown")` + muted caption |
| Model | `coding.model` | `metricRow("model", …)` mono verbatim | OMIT row if absent |
| Mode | `coding.mode` | `metricRow("mode", …)` | OMIT row if absent |
| Residency | `coding.residency` (`swap`/`shared`) | `metricRow("residency", …)` | OMIT row if absent |
| Token usage (per-model) | `report.usage.models[coding.model]` (USAGE-03 / D-09) | reuse existing usage rows: `metricRow("prompt tokens (total)", groupThousands(...))` + `metricRow("generated tokens (total)", groupThousands(...))` keyed to the coder model id | no entry → `mutedP("No usage recorded yet")` (NOT a fabricated 0) |
| Cache effectiveness | `coding.timings.cache_n` / `prompt_n` (USAGE-04 / D-10) | `metricRow("cache effectiveness", pct + " (" + cache_n + "/" + prompt_n + ")")` mono, e.g. `42.0% (84/200)` | timings absent/unparseable → `memoryBadgeRow("cache effectiveness","unavailable","unknown")` + muted caption — NEVER a fabricated 0% |

**Field-name discretion (CONTEXT.md → Claude's Discretion):** exact JSON spellings inside the
`coding` block are locked at plan time to match the Memory-block idiom (snake_case, `omitempty`).
The row LABELS above are the binding copy contract.

## Copywriting Contract

This is a read-only status panel — there is **no primary CTA and no destructive action**
(those belong to the Models panel, unchanged). Copy mirrors the Memory-panel voice: lowercase
row labels, sentence-case muted captions, honest Unknown wording (never a fabricated value).

| Element | Copy |
|---------|------|
| Panel heading | `Agent` |
| Primary CTA | none — read-only status panel (no action surface in this phase) |
| Row label — version | `version` |
| Row label — policy pin | `policy pin` (badge: `match` / `mismatch` / `unavailable`) |
| Row label — model | `model` |
| Row label — mode | `mode` |
| Row label — residency | `residency` |
| Row label — usage | `prompt tokens (total)` and `generated tokens (total)` (reuse existing usage copy verbatim) |
| Row label — cache | `cache effectiveness` |
| Pin mismatch caption | `Installed agent binary does not match the policy pin — re-install with villa install --coding-agent, or revert config.toml.` |
| Pin unevaluable caption | `Agent pin state unavailable.` |
| Usage empty state | `No usage recorded yet` |
| Cache Unknown caption | `Cache effectiveness unavailable — llama.cpp timings not yet observed.` |
| Empty state (panel-level) | none — the panel is hidden entirely when no `coding` block exists (no empty shell, D-05) |
| Error state | none panel-specific — a failed `/api/status` poll dims last-good content via the existing `setConnected` stale path + the global connection-lost banner (D-11, unchanged) |
| Destructive confirmation | none — no destructive action in this phase |

**Percentage rendering rule:** cache effectiveness shows one decimal with the raw ratio in
parentheses, e.g. `42.0% (84/200)`, computed only when BOTH `cache_n` and `prompt_n` are
present and `prompt_n > 0`. If `prompt_n == 0` or either is absent → the Unknown badge, never
`0%`.
