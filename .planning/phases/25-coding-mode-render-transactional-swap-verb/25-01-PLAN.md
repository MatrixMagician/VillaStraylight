<objective>
Build the CMODE-01 render delta: coding mode renders a tool-calling-ready `llama-server`
unit delta (`--jinja`, agent ctx via the single `-c`, the catalog sampling preset, and
`--cache-reuse 256` gated on `cache_reuse_safe`) BEHIND the `internal/inference` +
`internal/orchestrate` seams — driven entirely by new append-only `config.toml` fields.
With coding mode off, the rendered units and the config-on-disk bytes stay byte-identical
to v1.3 (D-02) and `TestSeamGrepGate` stays green.

Purpose: The coding-mode unit delta is the endpoint contract the Phase-26 agent launcher
and the Phase-27 install addon build on. Golden-freezing it FIRST (before the swap verb in
Plan 02, before the agent exists) is the research-converged build order: the byte-frozen
on-path golden becomes the immovable contract.

Output: `RunSpec.CodingMode *CodingModeSpec` descriptor + `CodingModeSpec` type; the
`ContainerArgs` delta append in both backend seam files; the seam gate extended to lock the
new flag literals; append-only `coding_mode`/`coder_*` config fields with omit-when-off
marshal; `orchestrate.Render` config→descriptor derivation; the NEW
`villa-llama-coding.container.golden`.

This plan is the realization of the locked decisions D-01, D-02, D-03, D-04, D-05.
</objective>
