<objective>
Build the CMODE-02 transactional enter/exit verb: a new pure, Deps-injected
`internal/codingmode` core that CLONES the `backendswap` transactional frame
(capture-before-mutate → mutate → under-load residency prove → verbatim rollback with honest
rollback-incomplete reporting) and COMPOSES the `modelswap` forward ordering for the model
change. A thin `villa coding-mode enter|exit` cobra noun wires the live host seams (reusing
`liveProve` as the cutover gate) and maps the typed `Result` to exit codes + messages.

Purpose: This is the user-facing capability of Phase 25 — flip the running stack into a
tool-calling-ready coding mode and back, transactionally, with residency proven under load.
A failed or degraded cutover is a no-op to the running stack (verbatim rollback). The mode
changes ONLY via this explicit verb (ROCm `backend set` precedent); nothing auto-flips it.
This verb is the endpoint the Phase-26 `villa code` launcher points Crush at.

Output: `internal/codingmode` core (`Run`/`Deps`/`Result`/`ProveVerdict`/`ProveStatusPass`,
literal-free of backend markers); `cmd/villa/coding-mode.go` (the noun + `liveCodingModeDeps`
+ Result→exit mapping); registration in `root.go`. Plus the on-hardware enter→prove→exit
acceptance checkpoint on the gfx1151 box.

This plan realizes the locked decisions D-06, D-07, D-08, D-09, D-10. It depends on Plan 01's
descriptor + config fields (the cutover renders the coding-mode unit from them).
</objective>
