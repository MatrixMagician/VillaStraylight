**RAG-env wiring dependency:** OWUI's RAG/embed env (`VECTOR_DB=qdrant`, `RAG_OPENAI_API_BASE_URL`
→ villa-embed, the Qdrant keys) currently appends ONLY inside the `memoryEnabled` block in
`buildOpenWebUIView`. BYPASS=False grounding needs those RAG keys. **DECISION: web search
REQUIRES memory-on (option a).** Rationale: it is the smaller surface (no refactor of the
memory block, no large memory-golden churn), it reuses the v1.3 RAG verbatim per the locked
decision, and the Phase-30 on-hardware UAT already ran with memory on. **Implementation:** do
NOT duplicate the RAG keys into the web-search block; instead, when `WebSearchEnabled &&
!MemoryEnabled`, the install/opt-in path must refuse with an actionable message ("web search
requires memory: run the memory opt-in first"). This coupling is documented in Task 1 and
enforced as a preflight/opt-in gate, NOT silently. (CONTEXT marks the RAG-env wiring choice as
Claude's Discretion; this is the documented choice.)
