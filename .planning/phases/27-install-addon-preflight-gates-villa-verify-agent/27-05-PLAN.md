<objective>
Close CR-01 (BLOCKER) and WR-05 from 27-VERIFICATION.md: make `villa install --coding-agent` serve the coder model it stages and gates on, and make the install readiness proof assert a REAL semantic replacement rather than mere token presence.

CR-01 root cause: `runInstall` sets `cfg.AgentEnabled = true` but never sets `cfg.CoderModel` / `cfg.CoderQuant` / `cfg.CoderAgentCtx` / `cfg.CodingMode`, and passes no `CodingMode` field to `d.render`. So `orchestrate.Render` (CodingMode == nil) keeps `villa-llama` serving the CHAT model at the default ctx, `agent.Render`'s `servedModelID` falls back to `cfg.Model`, and crush.json + the readiness proof + `villa verify agent` all target the chat model. The staged coder GGUF (`coderShard`) is dead-staged disk, and the disk/envelope preflight gates (driven by `rec.Coder`) reserve resources for a coder that is never run.

WR-05 root cause: `liveAgentToolCallProbe` declares success via `strings.Contains(edited, agentProbeTokenB)` only. An append (not replace), or a tool writing a transcript/confirmation containing TOKEN_B into the workdir, false-greens the readiness contract. The driver is shared by the install readiness proof AND `villa verify agent`'s agentTask, so hardening it once closes the honesty hole in both.

Architectural choice (resolved): the `--coding-agent` install ENTERS coding-mode and SERVES the coder during install (CR-01 fix option a, NOT option b). Rationale — honesty-by-construction (D-05) requires the readiness proof to exercise the model crush.json advertises; option b (render crush.json for the coder id without serving it) would leave the readiness proof probing a mismatched served model, the exact false-green the phase exists to forbid. This is consistent with D-04's "coding-mode is a separate verb" decision: the `villa coding-mode enter|exit` verb remains the runtime toggle, while `--coding-agent` is a one-shot install addon that brings the agent up PROVEN-READY (CONTEXT § Phase Boundary point 1: "comes up proven-ready"). The implementation REUSES the existing, golden-frozen Phase-25 helpers `codingDescriptor` / `codingServedTarget` / `codingModelFile` from `coding-mode.go` — the same path `coding-mode enter` already drives — so no new render contract is introduced and the catalog→inference translation stays in the live wiring (the pure renderer never imports internal/catalog, D-05).

Purpose: the headline addon must configure + prove readiness against the RIGHT model. A green install/verify signal must prove the coder the addon staged actually serves.
Output: a `--coding-agent` install whose inference unit, crush.json, readiness proof, and the downstream `villa verify agent` all target `rec.Coder.Model`; a readiness probe that asserts a true replacement; and two new off-hardware seam tests.
</objective>
