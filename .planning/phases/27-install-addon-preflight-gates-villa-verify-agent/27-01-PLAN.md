<objective>
Make the Crush coding agent an optional `villa install` addon, mirroring the memory addon seam-for-seam (INSTALL-03). This plan delivers the foundation every other Phase-27 plan consumes: the persisted `AgentEnabled` gate field (D-01), the new `install_agent.go` command file (coder-GGUF pre-stage resolved from the picked catalog entry per D-02, agent-binary install composed from the Phase-26 `agent.Install` seam per D-03, `crush.json` render, and the `evalAgentProof` tool-call readiness verdict per D-05), the Phase-27 security pass on the rendered config (`permissions.allowed_tools` + `options.disabled_tools` — Phase 26 deliberately deferred the restrictive allowlist to here), the FSL-1.1-MIT consent notice, and the `install.go` fold (`--coding-agent` flag + gate block per D-01).

Purpose: One install verb gates and stands up the addon; addon-off stays byte-identical to v1.3 (D-01). The coder GGUF the coding-mode unit serves and the staged filename derive from one catalog entry, so they cannot drift (D-04). The binary is staged through the Phase-26 checksum-before-extract seam, never re-implemented (D-03). The rendered config restricts tools (allow view/edit/write; disable the outbound fetch/download/sourcegraph tools — defense-in-depth for PRIV-06). Readiness is a real tool-call round-trip — a health-200 is a false-green and never passes (D-05).
Output: `AgentEnabled` config field; restrictive-tools render in `internal/agent/render.go`; `cmd/villa/install_agent.go` + test; `--coding-agent` flag + FSL notice + gate block in `install.go`; agent-off byte-identical render assertion in `install_test.go`.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| network → host (GGUF + binary pull) | The sanctioned outbound window fetches the coder GGUF (HF) and the Crush tarball (GitHub release) — untrusted bytes cross here |
| config.toml → crush.json render | A hand-edited config is untrusted input that drives the rendered provider/model ids + tool permissions |
| local model → host filesystem (readiness probe) | `crush run` drives a tool-call that reads/edits a planted file — the agent acts on the host |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-01 | Tampering | Coder GGUF download | mitigate | `download.PullModel` verifies SHA256 + exact size + atomic rename before use; presence-skip re-checks size — a truncated/tampered file is treated as absent and re-pulled (never served) |
| T-27-02 | Tampering | Crush binary tarball | mitigate | `agent.Install` does checksum-before-extract (`VerifyTarball` SHA256 vs the pinned policy asset) — mismatch refuses with remediation; no shell `tar`, traversal-confined extract (D-03) |
| T-27-03 | Spoofing/Tampering | Hard-coded coder shard literal | mitigate | D-02/D-04 single-source: the shard is resolved from the picked catalog entry, not a literal — eliminates a drift/forgery surface |
| T-27-04 | Information Disclosure | crush.json render | mitigate | `agent.Render` emits one loopback provider + both kill switches + `disable_default_providers`; config is the single source of truth, no shell interpolation |
| T-27-21 | Tampering/Info Disclosure (prompt-injection → outbound tool) | rendered tool permissions | mitigate | the render now sets `options.disabled_tools` (fetch/agentic_fetch/download/sourcegraph) + restrictive `allowed_tools` (view/edit/write) so the agent has no outbound tool surface — defense-in-depth for PRIV-06 (Pitfall 5 / Open Q3) |
| T-27-05 | Repudiation (false-green) | Install readiness | mitigate | `evalAgentProof` PASSES only on a real tool-call edit; a health-200 is never an input; a timeout/err is a FAIL with remediation, never a silent skip (D-05) |
| T-27-06 | Tampering (contract) | Seam-marker leak | mitigate | No backend-marker literal in `cmd/villa`; `TestSeamGrepGate` per task; the readiness driver uses no image literal (host binary exec only) |
</threat_model>
