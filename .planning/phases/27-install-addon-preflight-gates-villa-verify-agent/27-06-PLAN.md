Close WR-01 and WR-06 from 27-VERIFICATION.md — both honesty defects in `cmd/villa/verify_agent.go`'s live wiring of `villa verify agent` (PRIV-06).

WR-01 (PRIV-06 false-green): `liveAgentVerify`'s `egressBlocked` closure (verify_agent.go:129-134) returns `err != nil, nil`. ANY non-zero podman/curl exit — unpullable/missing helper image, missing `villa` network, podman daemon error, curl absent in the helper image, a typo'd host — is interpreted as "egress blocked = good". Because the negative control is the FIRST gate and the whole PRIV-06 verdict is gated behind it passing, a broken probe environment yields a PASSING control — exactly the false-green the negative-control-first design exists to forbid. The PURE core (`evalAgentVerify`) is already correct: it FAILs "could not run the probe" when `egressBlocked` returns an error (proven by `TestEvalAgentVerifyNegativeControlFirst`). The defect is entirely in the live closure collapsing every failure to `blocked=true`.

WR-01 in-network endpoint correction (the false-FAIL the checker caught): the robust fix runs a POSITIVE in-network sanity probe first to prove the probe environment works. That sanity probe MUST target villa-llama, and `runProbeCurl` runs INSIDE `villa.network` (a `--network villa` helper container) — so `127.0.0.1` there is the HELPER container's OWN loopback, not villa-llama. The agent task's `providerBaseURL = http://127.0.0.1:8080/v1` (internal/agent/render.go:32) is a HOST loopback for the HOST `crush` binary and is therefore the WRONG endpoint for an in-network probe: reusing it would make the sanity probe ALWAYS fail and thus FAIL the egress control on every healthy host (a false-FAIL substituted for a false-green). The in-network probe must reach villa-llama by its CONTAINER DNS name + server port — `http://villa-llama:8080/...` (the rendered unit's `ContainerName` = `villa-llama` in internal/orchestrate, `serverPort` = 8080 in internal/inference; the SAME in-network shape Open WebUI already uses in `internal/orchestrate/openwebui.go:124`). Both identifiers are UNEXPORTED, and a re-typed `villa-llama:8080` host literal in cmd/villa would violate the DNS-lockstep discipline (Pitfall 3 / T-4-01) that keeps the in-network host built from `containerName`, never re-typed. So this plan adds ONE exported seam accessor — `orchestrate.LlamaInNetworkEndpoint()` — composing the orchestrate container name + the inference server port, and `verify_agent.go` CONSUMES it instead of typing a host literal.

WR-06 (T-27-16 "never left stopped"): the llama-down control's deferred restore discards the Start error — `defer func() { _ = deps.systemd.Start(installServiceName) }()` (verify_agent.go:149). If Start fails (transient systemd error), the operator gets a PASS/FAIL verdict with villa-llama silently left DOWN and no surfaced error or remediation. For a verb that deliberately stops a core service, a restore failure is exactly what the operator must hear about.

The fixes are: (1) a new exported `orchestrate.LlamaInNetworkEndpoint()` seam accessor (so the in-network probe targets villa-llama, not the helper's loopback, with no re-typed literal); (2) `verify_agent.go`'s live seam (the egress closure + the llama-down restore); (3) a small probe-exit accessor in `install_memory.go`, which owns `runProbeCurl`. The pure `evalAgentVerify` core is unchanged — it already maps an `egressBlocked` error to FAIL.

Decision traceability: these fixes harden the controls locked in CONTEXT.md — D-06 (`villa verify agent` four-layer seam, PASS/FAIL only, an unevaluable result is a FAIL never a silent skip), D-07 (Control 1 egress / startup, negative-control-FIRST — the external egress probe under host egress block MUST FAIL to prove the block is real), and D-08 (Control 2 no silent cloud fallback, folded into the same verb via the llama-down control). WR-01 restores the D-06/D-07 honesty (a broken probe must FAIL, not pass) AND removes the false-FAIL (a healthy host must PASS the sanity probe by hitting the real in-network villa-llama endpoint); WR-06 protects the D-08 llama-down control's restore promise (villa-llama is never left silently stopped).

Purpose: the headline PRIV-06 control must prove egress is ACTIVELY blocked (a broken probe environment must FAIL, not pass) WITHOUT a false-FAIL on healthy hosts (the in-network sanity probe must reach the real villa-llama), and the verb that stops villa-llama must never leave it down silently.
